## 3. 质量门禁缺口与预算 top-up（计划 §4）

独立质量评估集（与校准集不重叠）实测：

| 数据集/规模 | 目标 | 校准 R | 校准集 recall | 质量集 recall | 处理 |
| --- | --- | --- | --- | --- | --- |
| SIFT 100K | 0.95 / 0.99 | 36 / 68 | 0.9509 / 0.9902 | 0.9562 / 0.9902 | 通过 |
| SIFT 1M | 0.95 | 58 | 0.9520 | **0.9485** | top-up → R=60 |

- SIFT 1M 0.95：ef 58 → 59（质量 0.9495，未过）→ **60**（校准 0.9544，质量 0.9506）；
- GIST 1M 0.99：ef 1739 → 1757（校准 0.9904，质量 0.9900，恰好达标）。

**披露**：top-up 复用了质量评估集，因此这两格的正式召回不再来自“完全未见”的样本；
原始 `calibration.json` 未被覆盖，新结果写入 `calibration_topup.json`
（`eval_split_reused: true`）。受影响的两格以新活动名重跑：
`sift_n1000000_static_q95`（进行中）、`gist_n1000000_static_q99`（排队，预计约 23 h）。

## 4. P2 混合：更新成本实测与协议缩减（需审批的偏差）

计划 §7 要求在跑矩阵前用 20 次代表性更新估算成本。实测（真实 RDMA、roundrobin）：

| 规模 | 单次更新延迟（20 次均值） | 20 次更新整轮墙钟 | 推算 100 次 |
| --- | --- | --- | --- |
| SIFT 100K | 518–536 ms | 18.2–18.7 s | ≈52 s |
| SIFT 1M | 6.42–6.78 s | 143.5–150.6 s | ≈11 min |

原因与计划预判一致：每次更新都会重写并重新注册整份索引（100K 索引 91 MB，
1M 索引 1.1 GB），与查询代价无关。按计划原口径（r = 0.1/0.3/0.5 × 计时窗口查询数）
在 1M 上单轮就要数小时，整矩阵不可承受。

因此 P2 按下列**缩减方案**执行，并在此登记为偏差：

1. 每轮固定 **100 次更新**（`UPDATES=100`），不再随 r 缩放；`r` 标签只表示更新在
   查询流中的**间隔密度**，本轮保留 0.1 与 0.5 两档，1M 只保留 0.5；
2. 因此**本轮不构成更新比例敏感性实验**，报告只给“固定更新预算下各策略的表现”；
3. 更新日志由 `scripts/prepare_update_log.py` 预先生成，全策略共享：
   `id = update_idx % n`（与驱动的 roundrobin 一致）、替换向量 `base[(idx + n/2) % n]`
   （真实分布、不与被替换节点相同）、erase 的 id 不重复、逐条 `vector_sha256` 可审计；
4. 检查点质量（0/25/50/75/100 %）由 `scripts/mixed_checkpoint_gt.py` 按当前活跃 ID 集合
   重算精确 float64 真值，`--phases checkpoints` 在**同一服务端会话**内先回放前 c 条更新再评测，
   回放与评测共享状态、回放查询不计入性能窗口。检查点评测为冷态（无预热），跨策略可比
   但与混合计时窗口的暖态不可直接互比。

未实现的偏差（如实登记）：`updates.csv` 只有 `update_idx/latency/ok/generation/error`，
**没有时间戳**（需改 C++ 驱动，本轮不变更搜索与存储实现），逻辑顺序与向量哈希由更新日志
清单提供；`insert`、hot/random 分布、查询更新真正重叠均为扩展项，未做。

## 7. 当前可下的结论与不可下的结论

可下：

- 真实数据上，M=16 的 G=32 与 B1 的 READ/query 和字节完全等价（SIFT 100K/1M、GIST 均成立）；
- 中间粒度 G=1/4/16 在 100K 上只增加过读（浪费率 0 → 0.24），延迟与 B3 差异在 ±1 % 内，
  未检出稳定优势；
- 1M 时 B1/G32 比 B3 快 1–3.6 %（区间不含 1），代价是字节流量高 1.3–1.5 倍；
- B2 的依赖读取让 READ/query 翻倍，在 SIFT 与 GIST 100K 上稳定慢 1.3–3.6 %。

不可下：

- 更新比例敏感性结论（本轮为固定更新预算，见 §4）；
- 并发扩展后的尾延迟与系统最大吞吐结论（P3 未完成）；
- 混合/更新后质量是否仍达标的结论（检查点阶段未完成）；
- 任何跨机拓扑结论。
