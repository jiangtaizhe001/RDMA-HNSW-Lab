# 科研轮转课题：面向动态图索引的分级读取优化机制

## 一、课题背景

随着向量数据库、推荐系统和图检索系统的发展，近似最近邻搜索已经成为大规模数据处理中的重要基础能力。HNSW（Hierarchical Navigable Small World）是一种常用的近似最近邻图索引。它通过在不同层次维护节点邻接关系，在较高层快速定位候选区域，再在底层图中进行精细搜索。

在实际系统中，图索引规模通常较大，无法全部放入计算节点内存。一个可行的系统架构是将计算节点和存储节点分离：计算节点负责搜索调度和距离计算，存储节点保存图索引数据，计算节点通过 RDMA 按需读取远程节点和邻居信息。这样可以提高内存利用率，也便于多个计算节点共享索引。

动态图索引会持续发生插入、删除和更新。节点邻居数量会随图结构变化而变化，计算节点缓存的邻居长度也可能失效。在这种场景下，如果每次都读取固定容量的全部邻居 slot，会传输大量无效数据；如果先读取 header 再读取实际邻居，又会增加依赖的网络往返；如果在计算侧缓存邻居长度，则需要处理更新导致的缓存失效。

本课题研究如何利用邻居长度信息和分级读取粒度，在查询性能、网络传输量、额外往返次数以及缓存开销之间取得平衡。

## 二、课题题目

**面向动态图索引的分级读取优化机制**

## 三、课题目标

本课题希望完成以下目标：

1. 理解 HNSW 图索引的基本结构和查询过程；
2. 理解存算分离架构下计算节点访问远程图数据的过程；
3. 在现有实验原型上实现三种邻居读取 Baseline；
4. 分析动态更新对读取开销和缓存有效性的影响；
5. 设计并实现一种分级前缀读取机制；
6. 通过真实 RDMA 实验比较不同机制的性能和适用场景。

## 四、实验原型介绍

本课题使用 `RDMA-HNSW-Lab` 作为实验原型。原型由以下部分组成：

- `hnsw_build`：构建 HNSW 图索引并保存为二进制索引文件；
- `storage_server`：独立启动存储节点，保存索引并提供 RDMA 访问；
- `compute_client`：用于快速验证系统功能的命令行客户端；
- `StorageNode`：可嵌入应用程序的存储节点接口；
- `ComputeNode`：可嵌入应用程序的计算节点接口；
- `RemoteTransport`：远程数据访问抽象，支持 mmap 和 RDMA；
- `NeighborReadStrategy`：邻居读取策略接口，是本课题的主要扩展点。

原型提供两种传输模式：

### 1. RDMA 模式

RDMA 模式中，存储节点和计算节点可以作为两个独立进程运行。存储节点注册索引内存，计算节点通过 RDMA READ 读取远程 header、向量和邻居数据；更新请求通过控制面提交到存储节点。

最终性能实验建议使用真实 RDMA 模式，因为该模式能够反映存算分离场景下的网络传输、RDMA 操作和控制面开销。

### 2. mmap 模式

部分同学可能没有带有 IB/RDMA 网卡的机器。为便于开发，原型提供 mmap 模式作为本地模拟后端。mmap 模式直接读取本地索引文件，可以用于：

- 熟悉索引格式；
- 调试读取策略；
- 验证查询和更新逻辑；
- 编写单元测试和小规模功能测试。

mmap 只能近似模拟远程数据访问，不能用于替代 RDMA 的最终性能结论。因此建议先使用 mmap 完成功能开发，再在具备 RDMA 的机器上完成正式实验。

## 五、课题内容

### 1. 理解索引和远程读取路径

需要理解索引文件中的 header、offset 表、节点记录、generation、邻居 degree 和固定容量 slot。需要跟踪一次 HNSW 查询从入口节点开始，如何读取节点向量、读取邻居并继续扩展搜索。

同时需要区分：

- 计算节点实际请求的字节数；
- 存储节点返回的字节数；
- 其中真正有用的邻居数据量；
- RDMA READ 操作次数；
- TCP 控制面或依赖读取带来的额外往返。

### 2. 实现 Baseline 1：完整读取所有邻居 slot

对每个访问到的节点和层，读取该层固定容量的全部邻居 slot，不根据实际 degree 缩短读取长度。

需要记录并分析：

- 查询延迟和吞吐；
- 每次查询的读取字节数；
- 有效邻居字节数；
- 无效传输字节数；
- 不同更新比例和图规模下的传输浪费。

该 Baseline 用于展示固定容量读取在邻居实际长度较小时产生的通信浪费。

### 3. 实现 Baseline 2：header-first 读取

第一次读取节点 header 或 degree 信息，获得实际邻居长度后，再读取后续邻居数据。

需要记录并分析：

- 额外读取操作次数；
- 依赖读取造成的额外往返；
- 查询延迟变化；
- 传输字节数变化；
- 动态更新场景下 degree 变化对性能的影响。

该 Baseline 重点分析减少无效传输和增加额外往返之间的权衡。

### 4. 实现 Baseline 3：计算侧缓存邻居长度

在计算节点缓存节点、层和 generation 对应的邻居长度。查询时优先使用缓存的长度确定读取范围，缓存可能过期，但第一次读取会带回 degree；当真实 degree 超过预测范围时执行 fallback 并更新缓存。

需要记录并分析：

- 缓存命中率；
- 缓存未命中次数；
- 缓存失效次数；
- 更新前后查询延迟；
- 不同缓存容量和更新比例下的性能变化。

该 Baseline 重点分析缓存减少额外往返的效果，以及动态图更新导致的缓存失效问题。

### 5. 设计并实现分级前缀读取机制

在三个 Baseline 的基础上，设计一种分级前缀读取机制。基本思路是将邻居 slot 划分为多个读取等级或前缀范围，根据查询阶段、历史信息、缓存状态或候选扩展需求逐步读取邻居前缀。

具体分级方式不预先限定。学生需要自行说明：

- 分级粒度如何定义；
- 第一级读取多少 slot；
- 何时继续读取下一级前缀；
- 如何利用 generation 或缓存信息；
- 如何保证查询结果正确性；
- 读取失败、缓存失效和更新并发时如何处理。

新机制应通过 `NeighborReadStrategy` 接口接入。

## 六、实验任务要求

### 1. 功能要求

- 支持构建并加载 HNSW 索引；
- 支持 mmap 和 RDMA 两种后端；
- 支持查询、upsert、insert 和 erase 等动态操作；
- 三个 Baseline 能够独立选择和运行；
- 分级前缀读取机制能够独立选择和运行；
- 查询结果和索引更新结果保持正确；
- 代码能够通过现有工程测试。

### 2. 实验设计要求

学生需要自行选择数据集、索引规模和 workload。

动态 workload 应同时包含查询和更新，并明确查询与更新的比例、操作顺序和持续时间。所有 Baseline 和新机制应使用相同的数据集、索引参数和 workload 进行比较。

### 3. 指标要求

指标由学生自行实现和记录，但至少应覆盖：

- 查询吞吐；
- 查询平均延迟和尾延迟；
- 更新延迟；
- RDMA READ/WRITE 操作数；
- 总传输字节数；
- 有效数据字节数；
- Baseline1 的传输浪费；
- Baseline2 的额外往返开销；
- Baseline3 的缓存命中率和失效率；
- 新机制在不同分级粒度下的额外开销、缓存命中率和性能变化。

实验程序不要求使用固定的日志格式。建议保存原始测量数据，再使用独立脚本进行统计和绘图。

### 4. 正确性要求

性能比较必须同时检查查询正确性。建议使用固定查询集、暴力搜索结果或已有 ground truth 计算 recall，测试结果应当在相同recall下进行比较，避免只比较速度而忽略结果质量。

### 5. 代码实现要求

学生提交的代码应满足以下要求：

- 三个 Baseline 和新机制必须是可以独立选择的读取策略；
- 每个策略都要有清晰的类名、`name()` 返回值和必要的注释；
- 不得修改 HNSW 搜索主流程来隐藏策略差异；
- 不得在读取策略中直接操作 ibverbs，统一通过 `RemoteTransport` 访问数据；
- 必须正确检查读取长度、degree、邻居 ID 和容量边界；
- Baseline3 和新机制必须处理缓存未命中、缓存预测错误和 fallback；
- 必须提供至少一个小规模正确性测试，验证不同策略返回结果一致；
- 必须保存策略源码、构建命令和运行参数，保证其他人能够复现实验。

### 6. 进阶挑战（可选）

在完成三个 Baseline 和基础分级前缀机制后，有余力的同学可以选择以下方向进行深入研究。进阶内容不作为所有同学的必做要求，但必须保持查询结果正确，并通过独立实验说明改进是否有效。

#### 6.1 自适应分级粒度

不再固定使用一个全局粒度 `G`，而是根据节点的历史 degree、缓存命中情况、fallback 频率或更新频率动态调整粒度。例如：

- fallback 频繁时增大 hint 等级；
- 长期过度读取时减小 hint 等级；
- 对热点节点和冷点节点使用不同粒度；
- 对高层邻居和底层邻居使用不同粒度。

需要记录粒度调整次数、调整原因和调整前后的性能变化。

#### 6.2 分层或分节点缓存

将缓存从“每个节点一个 degree”扩展为“每个节点每层一个 degree/hint”，或者进一步按照节点热度、更新频率和访问频率组织缓存。可以实现 LRU、LFU 或带代价的缓存淘汰策略，并比较不同淘汰策略的命中率和额外开销。

#### 6.3 并发安全的共享缓存

在多个查询线程之间共享长度缓存，研究读多写少场景下的并发访问方式。可以比较线程本地缓存、分片锁缓存、读写锁缓存和无锁原子版本缓存，但必须明确缓存更新、失效和 fallback 的同步语义。

#### 6.4 邻居数据批量读取和预取

根据候选队列或即将访问的节点，合并多个邻居区域的读取请求，或提前预取可能访问的节点。需要比较批量读取减少的 RDMA 操作数与无效预取带来的传输开销，并验证预取不会破坏查询正确性。

#### 6.5 更新感知的读取策略

根据更新类型和更新热点调整缓存策略。例如对频繁 upsert 的节点降低缓存等级，对长期未变化节点提高缓存等级；也可以研究 insert、erase 和 upsert 对 hint 失效概率的不同影响。

#### 6.6 快照和版本一致性优化

研究查询期间索引版本切换的处理方式，例如记录查询使用的 snapshot generation、在 fallback 前后检查版本是否一致，或比较旧快照继续完成与主动 reload 两种策略的代价。

#### 6.7 面向 RDMA 的异步读取

将同步的 `transport.read()` 改造成批量或异步读取接口，减少查询线程等待时间。该方向需要额外处理请求生命周期、完成通知、失败重试和读取结果的顺序，适合对 RDMA Verbs 和并发编程比较熟悉的同学。

#### 6.8 代价模型和自动策略选择

根据 degree 分布、更新比例、缓存命中率、RDMA 往返延迟和传输带宽，建立读取策略代价模型，并在运行时自动选择 Baseline2、Baseline3 或分级前缀策略。需要使用独立 workload 验证模型预测与实际结果之间的误差。

进阶实现应单独说明新增接口、线程模型、内存开销和失败处理方式，并与基础分级机制进行消融对比，不能只报告一个最终性能数字。

### 7. 动机实验

动机实验用于说明三个 Baseline 的局限性，不以证明新机制优越为主要目的。建议在相同数据集、索引参数和查询集下，设置静态查询以及包含动态更新的 workload。

- **Baseline1 动机实验**：记录固定 slot 读取的请求字节、有效字节和浪费字节，分析实际 degree 较小时的传输浪费；
- **Baseline2 动机实验**：记录 header 读取次数、依赖读取次数、RDMA 操作数和延迟，分析减少传输量时增加的额外往返；
- **Baseline3 动机实验**：记录缓存命中率、未命中率、缓存修正次数和 fallback 次数，分析更新比例、缓存容量和热点更新对缓存有效性的影响。

动机实验至少应包含一种动态更新 workload，并给出能够直接支持问题分析的图表或数据表。

### 8. 主对比实验

主对比实验比较 Baseline1、Baseline2、Baseline3 和分级前缀读取机制。四种策略必须使用完全相同的：

- 数据集、查询集和 ground truth；
- HNSW 参数（`M`、`ef-construction`、`ef-search`、`k`）；
- 查询线程数和更新线程数；
- 更新操作序列、更新比例和运行时长；
- 预热方式和统计区间。

主实验建议优先在 RDMA 模式下完成，至少报告查询吞吐、平均延迟、p95/p99 延迟、更新延迟、RDMA 读取操作数、传输字节数和 recall。结果应同时给出绝对值和相对 fixed Baseline 的变化。

### 9. 新机制参数敏感性实验

参数敏感性实验只针对分级前缀读取机制，分析参数变化如何影响性能和开销。至少测试：

- 分级粒度 `G = 1、2、4、8、16`；
- 缓存容量至少 2～3 个取值；
- 更新比例至少 0%、10%、30% 和 50%；
- 至少两种并发度；
- 至少一种随机更新和一种热点更新 workload。

每组实验记录：

- 查询吞吐和延迟；
- hinted degree 与真实 degree 的差异；
- 缓存命中率；
- hint under-estimate 次数；
- fallback 次数及 fallback 字节数；
- 向上取整造成的浪费字节；
- RDMA READ 操作数；
- recall。

需要分析是否存在最佳分级粒度，以及粒度过小、过大时分别受到何种限制。

### 10. 数据集、索引规模和 workload 要求

建议至少使用一个主数据集和一个扩展数据集：

- 主数据集推荐 SIFT1M，可先使用 10K、100K 子集开发，再使用完整数据集；
- 扩展数据集可选择 GIST1M、GloVe-100 或 Deep1M，用于观察维度和数据分布的影响。

主实验至少应设置三个索引规模，例如 10K、100K 和 1M；如果硬件资源有限，可以使用等比例子集并在报告中说明限制。动态 workload 至少应包含查询、upsert、insert 或 erase 中的两类操作，并明确查询/更新比例、操作顺序、并发线程数和持续时间。

最终 RDMA 实验应固定一套主配置用于横向比较，再改变一个因素进行敏感性分析，避免同时改变多个因素后无法解释结果。

## 十一、建议使用的公开数据集

建议优先选择带有标准查询集和 ground truth 的 ANN 基准数据集。Faiss 的公开数据集工具提供 SIFT1M、GIST1M、Deep1B 和 GloVe 等数据集的读取方式，ANN-Benchmarks 也整理了常用数据集的维度、规模、距离类型和下载入口：[Faiss 数据集工具](https://github.com/facebookresearch/faiss/blob/main/contrib/datasets.py)、[ANN-Benchmarks 数据集列表](https://github.com/erikbern/ann-benchmarks/blob/main/README.md)。

| 数据集 | 典型维度和规模 | 距离 | 建议用途 |
| --- | --- | --- | --- |
| SIFT1M | 128 维，100 万 base、1 万 query | L2 | 首选入门数据集，适合调试、Baseline 对比和 RDMA 小规模实验 |
| GIST1M | 960 维，100 万 base、约 1 千 query | L2 | 观察高维向量对读取字节数和查询延迟的影响 |
| Deep1M / Deep1B | 96 维，可从百万级扩大到十亿级 | Angular/内积近似设置 | 先使用 Deep1M 验证，再根据存储容量选择更大规模实验 |
| GloVe-100 | 100 维，约百万级向量 | Angular/内积 | 测试内积距离、文本向量分布和缓存行为；来源见 [Stanford GloVe](https://nlp.stanford.edu/projects/glove/) |

推荐顺序是：先使用 SIFT1M 的 10K 或 100K 子集完成 mmap 开发，再用完整 SIFT1M 做 Baseline 对比，然后使用 GIST1M 或 GloVe-100 检查维度和数据分布变化，最后使用 Deep1M 或更大规模数据进行 RDMA 实验。

这些数据集通常不是本项目的 fvecs 格式。使用前需要转换为本项目格式：每条记录由 little-endian `int32` 维度和连续的 `float32` 分量组成。转换时需要同时保留 base、query 和 ground truth，并确认距离定义一致。报告中应记录数据集版本、下载地址、转换脚本、数量、维度、距离函数和 ground truth 生成方式。

## 十二、建议的七周安排

### 第 1 周：系统和背景学习

学习 HNSW 基本原理、索引文件结构、RDMA 基础和项目代码组织。完成工程构建，跑通 mmap 查询示例，并阅读主要公开 API。

### 第 2 周：原型和数据准备

理解存储节点、计算节点、查询引擎和 transport 的数据流。准备至少一个小规模数据集和一个查询集，完成索引构建及正确性验证。

### 第 3 周：实现 Baseline 1 和 Baseline 2

实现完整 slot 读取和 header-first 读取。确认两种策略的查询结果一致，记录读取操作、传输字节数和延迟。

### 第 4 周：实现 Baseline 3

实现计算侧邻居长度缓存，处理动态更新和缓存失效。测试不同更新比例和 workload 下的命中率与性能。

### 第 5 周：设计并实现分级前缀读取

提出分级读取方案，明确分级粒度、读取条件、缓存策略和正确性保证。通过 mmap 完成功能调试，再迁移到 RDMA。

### 第 6 周：完整 RDMA 实验

在具备 IB/RDMA 的环境中部署独立存储节点和计算节点，运行查询、更新以及混合读写 workload。完成 Baseline 和新机制的统一对比。

### 第 7 周：参数分析和总结

测试不同分级粒度、缓存容量、更新比例和并发度，分析性能变化和适用范围，整理实验数据、图表、代码和结题报告。

## 十三、开始前建议学习的知识

### 必备知识

- C++ 基础：类、继承、模板、智能指针、STL、线程和锁；
- Linux 基础：进程、文件、网络、shell、CMake 和 gdb；
- 数据结构：图、优先队列、哈希表、堆和基本复杂度分析；
- 向量检索：欧氏距离、内积、近似最近邻和 recall；
- 并发编程：线程、互斥、原子变量、读写锁和基本竞态分析。

### 建议学习

- HNSW 的分层图结构、入口点、邻居连接和 beam search；
- RDMA 的 PD、MR、QP、CQ、WR、completion 和 one-sided READ/WRITE；
- InfiniBand 设备、端口状态、`ibstat`、`ibv_devinfo` 等工具；
- mmap、pread、文件描述符和原子文件发布；
- CMake target、静态库、头文件和链接依赖；
- 基准测试设计、延迟分位数、吞吐统计和实验可复现性。

不要求在开始前掌握所有 RDMA Verbs 细节。建议先通过 mmap 跑通系统，再理解 RDMA 数据路径。
