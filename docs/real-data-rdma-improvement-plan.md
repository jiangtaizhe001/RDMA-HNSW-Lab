# 真实数据、1M RDMA 与重复实验改进计划

状态：待实施；本文件是实验协议，不表示数据已下载、脚本已适配或实验已完成。日期：2026-11-08。

## 1. 已完成工作与本轮边界

本轮接受“通过调整 efsearch 可以达到约 0.95/0.99 recall”的已完成结论，不再将修改搜索算法作为前置任务。依据 [十规模阈值报告](prefix-g32-efsearch-report.md)，历史结果如下：

| 合成数据规模 | 约 0.95 的中点预算 / 实测 recall | 约 0.99 的中点预算 / 实测 recall | 严格达标的历史实测上端点 R |
| --- | --- | --- | --- |
| 10K | 214 / 0.9498 | 402 / 0.9897 | 216 / 404 |
| 1M | 12726 / 0.9499 | 41910 / 0.9900 | 12728 / 41912 |

中点表示阈值估计，约 0.95/0.99 不等于未四舍五入的数值严格达标。以上预算仅适用于历史合成数据、指定图与查询集，不能直接迁移至 SIFT/GIST。已有 1M 证据是 mmap 质量测量，不是 1M RDMA 性能验证；历史 GT 解码问题及其修正以阈值报告为准，不继续沿用旧低 recall 的单一归因。

本轮只解决以下证据缺口：真实数据分布、1M RDMA 规模、混合与并发独立重复、统计可信度，以及部署条件的外推限制。

- 严格沿用 `search_semantics=prototype_expansion_budget`，不实现标准 HNSW、不修改 C++ 搜索流程，不新增搜索模式。
- 首期变更限于实验脚本、分析脚本和文档；复用现有读取策略、构图工具、实验驱动与 GT 工具。
- 高 recall 的可达性已验证，但仍需报告对应时延和资源成本；不将原型 efsearch 与标准 hnswlib 的 ef 混同。
- 不覆盖旧索引、原始结果或历史报告，不用新增结果追溯改写旧实验事实。

## 2. 研究问题与比较原则

1. 真实数据上，中间粒度 G 是否仍仅增加过读，还是存在优于 B3 的可重复折中？
2. 从 100K 到 1M，在相同质量目标与可比缓存预算下，READ、字节和端到端性能如何变化？
3. 动态更新中，收益来自冷启动覆盖、减少缓存低估补读，还是仅由测量波动造成？
4. 客户端增加后，各策略的吞吐、尾延迟和公平性如何变化？

每个比较单元固定数据、索引、查询顺序、更新日志、efsearch、质量目标、缓存预算和传输后端。各策略不单独调参以制造优势。优先比较 B1、B2、B3、QP G=1/4/16/32；G=2/8 只用于完整粒度扩展扫描。M=16 时 G=32 覆盖 L0 容量，结论需明确这一退化为固定读取的边界。

## 3. 数据集、规模与真值

| 数据集 | 维度 / 距离 | 调试规模 | 正式规模 | 地位 |
| --- | --- | --- | --- | --- |
| SIFT1M | 128 / L2 | 10K | 100K、1M | 必做主实验 |
| GIST1M | 960 / L2 | 10K | 100K、1M | 必做跨数据集静态验证 |
| 历史合成均匀数据 | 128 / L2 | 复用 | 历史十规模 | 对照，不替代真实数据 |

数据从原始发布渠道取得，保存来源 URL、版本、使用条件、压缩包和解压后 SHA-256。执行前确认可获取性及存储空间；无法取得的数据集标记 blocked，不以合成数据冒充替代。

1. 复用 [convert_sift.py](../scripts/convert_sift.py) 的 fvecs 准备能力，另行校验每条维度头、有限值、记录数、字节序和 ID 映射；不得仅凭脚本名假定格式正确。
2. 子集固定为原始 base 的前 N 条并保存映射，每个规模独立构图，不截断大索引；报告前缀抽样的代表性限制。构图 M=16、ef_construction=200，主种子 42。
3. 官方查询集按固定随机排列划分为不重叠的校准集与质量评估集；默认各 1000 条。剩余查询用于性能测量，按数据集实际数量记录，不虚构独立样本数。
4. 每个规模计算对应精确 top-10。不能过滤全量 top-10 代替子集 GT；官方全量 GT 也须验证距离、ID 和并列距离处理。
5. 1M GT 优先使用分块精确 L2 或 Faiss `IndexFlatL2`，不是近似索引；记录精度、批大小、内存峰值和并列规则。复用 [compute_gt.py](../scripts/compute_gt.py) 时先评估 float64、距离块及全排序的开销，不直接照搬为大规模默认方案。
6. 每个数据集/规模固定抽取至少 10 条查询，以独立直接差平方和重算 top-10，核验 ID 范围、重复项及第 10/11 名并列。质量评估集和校准集均生成独立 GT。

GIST1M 仅 float32 base 约 3.84 GB，索引、GT 工作区、RDMA 注册和多进程还需额外空间；以 pilot 实测 RSS 和注册内存为准，不按索引文件大小推断所有资源。

## 4. 真实数据的质量预算校准

这是迁移到新数据的参数校准，不是重新修复召回率问题。

- 每个数据集、规模和构图种子分别在校准集上定位 0.95、0.99 的预算，复用 [阈值计划](prefix-g32-efsearch-plan.md) 的按需括区间与整数二分思想。
- 正式预算取未四舍五入 recall 达标的实测上端点 R，不取可能未达标的区间中点。历史预算只作 pilot 起点，不按 N 比例外推。
- 在独立质量评估集上报告实际 recall。若不达目标，不把该组写成达标比较；只用校准集按预定预算序列递增选择新预算，记录每次评估，最终评估集不再作为完全未见测试集宣传。
- 静态下，各策略以相同预算检查返回结果的一致性，至少检查 recall、错误数及邻居序列。现有 CSV 不含结果 ID 时，不声称完成逐查询结果 ID 一致性验证；需另行具备导出能力或明确采用较弱门禁。
- mmap 可用于便宜的质量校准；正式 RDMA 先复核同索引同查询质量。两后端不一致先停止排错，不能用提高预算掩盖读取错误。
- 校准成本与正式性能成本分开，不能把 GT 计算或阈值搜索时间计入查询延迟。

扩展矩阵：G=2/8、GIST 混合与并发、0.99 混合与并发、insert、热点更新、查询更新重叠、第二种 M、跨机构图种子复现。扩展项不能静默变成必做项的替代品，也不将未做扩展标为失败。

P1 开始前，先在 SIFT 100K、0.95 下对 7 配置做缓存容量 1000/10000/100000/200000 的预注册扫描，每格 5 次。主矩阵统一使用 100000 条缓存上限；SIFT 1M 的 B3/QP G=16/32 另做相同比例容量 1000000 的补充扫描，每格 5 次。条目数不是严格相同字节预算，须记录或估计元数据、容器及条目实际开销，不宣称已实现等内存比较。

## 6. 单轮运行与稳态定义

- 每个独立重复重新启动客户端和服务端；混合轮次恢复同一初始索引副本，校验哈希，禁止继承上一策略的更新状态或长度缓存。
- 同一重复内共享查询和更新日志，不同重复使用预先生成并保存的排列种子；策略顺序按固定随机种子打乱或均衡轮换，避免始终让同一策略先执行。
- 静态每轮先记录至少 1000 条冷查询，再进行预先固定的预热阶段，随后计时至少 10000 条查询且至少 60 秒，两条件同时满足。查询不足时循环固定序列并明确标注重复，不把循环当成新增独立查询。
- 用 pilot 的命中率/READ 时间序列选择预热长度，冻结后所有策略一致执行；正式阶段未稳定则报告时间趋势，不事后挑选最好窗口称为稳态。
- 混合每轮至少 1000 条查询，按固定调度生成实际更新数；尾延迟样本不足 10000 时不将 p99 作为可靠主结论。查询不足可增加，但不得测后只保留有利窗口。
- 记录 CPU/NUMA 绑定、客户端线程、服务端线程、BLAS 线程、频率策略、其他负载和页缓存条件。不能将 mmap 页缓存控制当作 RDMA 长度缓存预热。

## 7. 混合 workload 与更新成本

主实验采用现有串行交替模型，不将其描述为查询与更新真正重叠。定义 `r=成功更新数/查询数`，同时报告更新在全部操作中的占比 `r/(1+r)`；0.1/0.3/0.5 对应约 0.091/0.231/0.333。失败更新另计，不能当作成功操作。

erase 每轮不重复删除同一 ID，保留足够活节点；upsert 使用固定目标 ID 和固定替换向量，保存所有操作的逻辑顺序、结果、时间戳及向量哈希。默认 roundrobin，hot/random 作为扩展，禁止运行后挑选最有利模式。

在初始状态及 25%/50%/75%/100% 进度检查点，针对当前活跃向量与 ID 集合离线重算评估 GT。检查点质量查询不进入性能统计，不改变下一计时段的缓存；可用独立评估客户端和同状态索引完成。删除 ID 不得返回，更新向量必须参与真值。记录实际 recall，不因预算由初始图校准就默认更新后仍达标。

分别报告查询服务延迟、更新延迟、包含更新等待的整轮查询吞吐与操作吞吐；没有请求到达模型时，不声称测得排队响应延迟。记录冷补读、缓存低估补读、degree 变化和桶内增长可观测证据；无法从现有计数器区分的原因写作推断，不冒充直接测量。

历史更新由整份索引重写与重新注册支配。执行前用 20 次代表性更新估算 1M 总成本。首期不改存储更新架构；若成本不可承受，发布阻塞及已完成范围，单独审批缩减方案。将增量更新优化另立任务，不能混入本轮使策略对照失去共同实现。

## 8. 并发与网络部署

- 每组创建 1/2/4/8 个独立 ComputeNode，缓存互不共享；客户端采用固定且可复现的查询分片，策略间保持一致，单客户端缓存上限固定并报告聚合内存。
- 所有客户端完成连接和预热后设置启动屏障，采用统一测量窗口；记录每客户端起止时间，确认有效重叠。现有驱动若不能提供屏障，先适配脚本可控制的机制；不能实现时列为阻塞，不把异步启动近似成同步实验。
- 聚合 QPS 为共同窗口内完成查询数除以窗口时长，不简单相加不同时间段的客户端 QPS。启动、连接和建图开销另列。
- 报告每客户端 QPS、p50/p95/p99、汇总查询分布及 Jain 公平性指数；不能对客户端 p99 求平均冒充总体 p99。
- 测量端到端服务曲线至资源饱和或 8 客户端，记录 CPU、内存、HCA 流量、链路状态和错误；未饱和时不宣称系统最大吞吐。

两机 RDMA 为优先部署：存储与计算分别位于物理主机，记录 HCA、固件、链路速率、MTU、NUMA、操作系统及 RDMA 配置。先完成跨机 smoke，再执行正式矩阵。若仅有单机 IB loopback，可以完成本机矩阵，但明确其不能解决跨机 RTT 外推问题；跨机验证作为独立未完成项，不以重复次数抵消拓扑限制。

## 9. 指标与统计协议

每轮保存逐查询原始数据、独立摘要、更新日志和监测信息。至少报告：

- 实际 recall@10、读取失败数、查询与更新成功数；质量核验与计时窗口的关系。
- 查询均值、p50/p95/p99、QPS、更新延迟，以及包含更新的整轮墙钟吞吐。
- 邻居 READ/query、依赖 READ/query、node_reads/query、节点头与向量字节、邻居请求/有效/浪费字节及总远程流量口径。
- 缓存命中/未命中、淘汰、冷补读、缓存低估补读和分级过读；按可用计数器校验操作与字节恒等式。
- 构图时间、索引大小、计算端与服务端 RSS、注册内存和缓存预算；不能只凭邻居流量评价 GIST 总成本。

以独立运行作为重复单位，同一轮中共享 workload 的策略采用配对比较。主比较预先固定为 QP 各 G 对 B3，B1 为固定读取参照，B2 为依赖读取参照；报告每轮数据、运行级中位数与配对差值/比值的 95% bootstrap 置信区间，固定随机种子和重采样次数。5 次只是起始重复数，区间可能较宽，应如实报告，不把一轮内上万条相关查询当作上万个独立运行。

若主比较不确定，按预定顺序将该比较单元的所有策略一起补至 10 次；之后仍不确定则报告“未检出明确差异”。增加重复后沿用最终样本量统一分析，披露追加规则，不挑选中途显著结果。多个 G 同时作显著性结论时使用多重比较校正，或明确仅作描述性区间分析。

构图种子与运行重复分层呈现，不将 P4 的多种子运行直接混为单图方差。质量区间需要逐查询命中信息；现有 CSV 无此信息时只能报告支持的指标，不从单一平均 recall 伪造置信区间。

## 10. 脚本适配、资源与复现

优先复用 [run_rdma_prefix_100k.sh](../scripts/run_rdma_prefix_100k.sh)、[analyze_prefix_sweep.py](../scripts/analyze_prefix_sweep.py) 和现有阈值工具；以下为待实现接口，不表示当前脚本已经支持：

1. 参数化 dataset/N/dim/index/query/GT/efsearch/seed/重复数/客户端数/缓存/拓扑，去除写死的 synthetic、100K 和 efsearch=64 标签。校准结果以独立映射输入运行器。
2. 将 MIX_REPS、CONC_REPS 从单次协议调整为正式 5 次协议，校验实际完成数量，而不只修改默认数字。
3. 新结果进入仓库相对路径 `out/real_data_rdma/<campaign>/`，输入进入独立数据目录；manifest 固定全部参数、代码版本、二进制与输入哈希、环境、随机种子和计划矩阵。
4. 每个 run 保存命令、stdout/stderr、开始结束时间、退出码、summary、per_query、更新日志；退出成功且行数、身份、质量和账本检查通过后才发布完成标记。
5. 续跑键纳入协议、数据/索引/GT/二进制哈希和全部关键参数；不能仅凭 CSV 非空跳过，不复用旧 100K 完成标记。
6. pilot 对每类数据规模、质量档、更新与并发测时间和资源，生成单轮及整个矩阵估时。1M 高预算不能按历史 efsearch=64 的成本估算。
7. 长任务使用可恢复的持久化调度，记录任务身份、日志、心跳、状态与预计完成时间。完成发布前核实全部必做单元，不将部分完成标记当作全量完成。

执行前检查磁盘、RSS、注册内存与可用 CPU，保留安全余量；不承诺未经 pilot 的固定完成日期。资源不足时保留原协议，另行记录缩减提案与批准状态；超时、缺查询、少重复和未达质量的结果不能算成功完成。

## 11. 交付与验收

按 P0 → P1 → P2/P3 → P4 执行，每阶段先验收再扩大规模；P2/P3 可独立排期，但共享硬件时不同时运行以免互相干扰。新增脚本先做小规模 smoke、语法/数据校验，再执行正式任务，避免立即启动全矩阵。

最终提交原始数据清单、可复现命令、完成/失败矩阵及一份新报告。图表至少包含同质量下的延迟与 QPS、READ 与字节折中、100K→1M 变化、更新比例敏感性、客户端扩展曲线及重复运行区间。

验收要求：

- SIFT/GIST 的 100K/1M 静态真实 RDMA 证据齐全，不用 mmap 时延替代。
- 主矩阵每格至少 5 次有效独立重复；混合、并发不再以单次运行概括稳定性。
- 新数据的质量预算独立校准，正式质量实测且策略口径一致，未达标与读取异常明确隔离。
- 动态 GT 对应当前状态，并发计量对应共同时间窗口，冷态与稳态不混用。
- 失败、资源限制、未实施扩展及 loopback/跨机范围清楚列出；所有必做项完成前，报告状态只能为部分完成或阻塞。

允许最终结论仍是“G=32 等价于 B1，中间 G 未表现出稳定优势”。本轮目标是提高外部有效性和证据可靠性，不以新机制必须胜出作为验收条件。
